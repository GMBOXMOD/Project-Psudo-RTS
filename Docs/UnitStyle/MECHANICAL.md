# 机械单位适配

本分支与[通用风格指南](../UNIT_MODELING_STYLE.md)共同使用。这里规定如何让车辆、机甲、飞机和机械装置沿用 M1A1 的表达方法，不要求它们复制 M1A1 的车体、履带或配色。

工厂、炮塔、经济设施等 RTS 建筑先读[建筑分支](BUILDINGS.md)，再用本分支处理其中的活动机械；占地、生产出口和建筑状态不能只用移动单位规则代替。

## 1. 先建立结构逻辑

制作前明确五件事：

1. **承载**：车体、机身或躯干承担什么重量，主要结构怎样连接。
2. **推进**：轮、履带、足、旋翼或喷口在哪里，运动时哪些部分会变化。
3. **功能**：主装备、工具、货舱或传感器哪一项定义单位角色。
4. **活动范围**：关节、炮塔、炮管、舱门等各自绕什么轴运动。
5. **识别锚点**：哪些形体必须保留，哪些设备只是点缀。

灰模应能回答这些问题。先用大体积与留白解释功能，再补小设备；不要靠把零件堆满表面来制造“机械感”。

## 2. 按类别提炼，而不是套用坦克模板

| 类别 | 优先保留 | 简化路径 | 主要检查视角 |
| --- | --- | --- | --- |
| 履带／轮式车辆 | 轴距或轮组节奏、离地间隙、车体比例、上装轮廓 | 简化轮毂、履带花纹、挡泥板和小挂件 | 侧面、前面、游戏俯视 |
| 机甲／机械兽 | 支撑足、腿段比例、关节位置、躯干和主装备 | 合并同一刚性段上的小护甲与管线 | 前侧、侧面、步态关键帧 |
| 飞机／飞行器 | 机身与翼面关系、翼展、尾翼、推进器布局 | 用大面表达翼型，减少微小铆钉和装饰缝 | 顶面、侧面、常用空战视角 |
| 工程／运输单位 | 工作装置、装载空间、底盘、开合／伸缩关系 | 保留工具开口与运动范围，压缩次要设备数量 | 工作姿态、收纳姿态、俯视 |
| 固定机械装置 | 功能主体、朝向、底座与支撑 | 把重复设施归并为少量功能块 | 俯视、主工作方向 |

同一功能的两个单位，应通过至少一个稳定的形体特征区分。微小编号或颜色小点不是唯一识别手段。

## 3. 几何表达

### 3.1 壳体与装甲

- 用少量连续截面、斜面和楔体构成主壳体，保持外轮廓完整。
- 大平板拥有安静区；板缝只标出重要结构分区。
- 分层装甲表现为有限的厚度与转折，不把每块平板都重复套边或满铺凸块。
- 在容易读到的边缘保留厚度；遮挡处和不影响轮廓的背面按实际需要处理。
- 倒角数量服从游戏视距。需要一个明显斜面时直接建这个面，而不是用密集小倒角假装细节。

### 3.2 圆形件与细杆

M1A1 用八边形轮子和多数八边形圆柱保留低模分面。其他机械件可把 **6–12 边**当作起点，再按占屏尺寸、旋转表现和外轮廓调整；这不是硬性边数范围。

轮子可以用轮胎、轮面和中心轮毂三个大层次表达；传动零件保留大小关系而非每个螺栓。细杆、炮管和天线如果在正常视距闪烁，优先调整厚度或合并，而不是加很多径向分段。

### 3.3 重复件

区分两类重复：

- **结构节奏**：车轮数量、明显的腿段、主要进气口等可能属于识别锚点，应保留必要节律。
- **表面噪声**：每个铆钉、散热片薄边、小螺孔等通常可以合并或省略。

复用网格可以减少源文件重复，但不会消除每个实例的显示和运动成本。不要把“只有一个轮子网格”当作“整辆车只算一个轮子”。

## 4. 把表面信息压缩成明确符号

| 信息 | 本风格的表达 |
| --- | --- |
| 通风／散热区 | 少量宽槽或大色带，必要时一块浅凹面 |
| 观察窗／镜片 | 清楚的小窗口轮廓与克制的冷色，而非复杂镜头组 |
| 战术／阵营标记 | 一个在正常视距能读到的大图形，留足背景 |
| 金属／橡胶差异 | 大色区、适度反射差异和结构位置共同说明 |
| 布包／储物篮 | 保留外轮廓与大支架，省略布纹和细网 |
| 灯和警示部件 | 少量位置准确的点缀，不把全机变成发光边框 |

浅色壳体配深色轮履是 M1A1 的一个成功组合；绿色、灰色或其他阵营涂装同样可以使用。迁移时保留明暗职责，而不是强制沙色。

## 5. 分件与运动

### 5.1 按“独立运动”分件

同一刚性壳体内、不需要独立运动的小装饰可以合并。旋转、俯仰、后坐、开合和伸缩部件各自拥有合适的局部枢轴；发射点等逻辑定位节点可以没有可见网格。

M1A1 的层级 `Base → Turret → Gun → Flare` 解释了炮塔、炮管和炮口的关系。新的机械单位按实际结构命名，不为了套脚本给所有单位都造一套同名炮塔。

建模时就检查可动空间：

- 炮管俯仰时是否碰壳体，后坐时是否穿过炮塔后壁。
- 轮子、履带与挡泥板是否干涉，转向时哪些部件真正发生相对运动。
- 机械腿摆动是否需要额外间隙，工具展开是否改变碰撞范围或占地。
- 不同单位是否错误共享动画状态，而不仅仅是共享控制器代码。

### 5.2 用功能表现重量

- 轮履速度跟随实际移动，左右履带在转向时可以不同速；停止后保持合理状态。
- 重型车体的姿态由地形与真实运动解释，不额外叠加与速度无关的循环弹跳。
- 武器后坐由发射触发，恢复动作比瞬间跳回更能解释机构。
- 机械腿拥有支撑相与摆动相，足底接地和重心转移需要一起看。
- 旋翼、喷口、传动件是否需要动画取决于任务范围；静态装饰不应被宣传成已实现功能。

这不禁止弹性悬挂或风格化反馈。需要这些表现时说明物理或角色原因，并避免与引擎已有的地形姿态重复叠加。

## 6. 一次可迁移的制作示例

任务：同风格的四足工程机甲。

1. 锚点选为低位货舱、四条外张支撑腿、前置抓具；先用灰模确认轮廓和抓具开口。
2. 躯干用两三个连续壳体块，腿分成实际需要运动的刚性段，关节保留间隙。
3. 用主涂装、暗色机械关节、少量玻璃和阵营标记组织颜色。
4. 抓具齿形只保留大尺度节奏，管线归并到少数明显走向。
5. 检查行走与工作姿态的负空间，检查抓取动作是否穿插。
6. 最后与 M1A1 在相近占屏尺寸下对照细节密度，并按目标引擎检查分件。

这里沿用的是表达层级，没有复制坦克的沙色、七轮或 102 节点结构。

## 7. 分支验收补充

- [ ] 主体、推进、功能装置与承重关系在灰模中成立。
- [ ] 重复件的必要节奏得到保留，表面微件已做取舍。
- [ ] 关键活动部位的层级、枢轴与运动空间匹配。
- [ ] 运动对实际位移、转向或触发事件有因果关系。
- [ ] 新单位所用脚本与节点契约经过核对，而不是盲目沿用 M1A1 名称和数量。
