# Recoil 单位与建筑资产流程、技术边界

本分支用于导出、接入和验证，不定义其他引擎的通用格式要求。艺术目标以[通用风格指南](../UNIT_MODELING_STYLE.md)为准，M1A1 的运行说明以[M1A1 测试文档](../M1A1_TESTING.md)为准。

## 1. 当前项目链路

项目当前的 M1A1 从[生成器](../../tools/build_m1a1.py)生成几何、贴图、分件、履带参数和预览，复用[既有导出基础函数](../../tools/build_ztz99a.py#L618-L713)。游戏通过[单位定义](../../Units/m1a1.lua#L5-L17)加载原生模型及 Lua 脚本。

| 产物 | 当前用途 | 新单位应保留的能力 |
| --- | --- | --- |
| 可编辑生成源或 DCC 工程 | M1A1 使用 Python 生成源 | 能解释、修改并重建交付；不要求所有单位都用同一种建模工具 |
| S3O | 当前游戏实际加载的模型 | 与目标游戏支持的模型链路一致，不能仅改文件扩展名 |
| GLB | 同源交换与检查文件 | 保留合理的几何、材质和层级；不冒称引擎直接使用它 |
| 两张原生贴图 | 颜色／队色与材质／可见性通道 | 按当前原生材质契约生成和检查 |
| 单位脚本及必要参数数据 | 驱动分件与动作 | 与节点、轴和尺寸一致；动态数据有清楚来源 |
| 图标、多视图、统计清单 | 构建界面和验证证据 | 能以正常视距检查外观，能核对实际预算 |

新单位可以使用别的建模方式，但应证明最终资产在目标链路中工作。M1A1 的文件名、轮数、节点数和碰撞尺寸不是通用模板参数。

## 2. 坐标、尺寸和枢轴

当前项目建模约定为 **X 向右、Y 向上、Z 向前**。从不同坐标系的 DCC 工具导出时，显式处理轴向和单位比例，再验证正面、地面和朝向。

- 模型空间与每个 piece 的局部空间分开；子节点偏移相对于父节点。
- 独立转动部件的局部原点落在实际转轴，而不是任意的网格中心。
- 发射点、观察点等可以是空节点。保留脚本需要的定位信息，不为避免“空网格”而给它加一个可见方块。
- 原生模型的包围体、单位碰撞体与视觉体量需要分别检查；不要把所有附肢的最大包围盒直接当作游戏占地。
- 生物的地面高度、重心、翅展和极限姿态按自身结构计算，不能复制坦克的高度、中心或碰撞盒。

M1A1 当前层级为 `Base → Turret → Gun → Flare`，轮履也是 `Base` 的子节点，见[模型组装](../../tools/build_m1a1.py#L270-L280)。这是一套具体的脚本契约，而非必须沿用的通用命名。

## 3. 法线、三角化与静态姿态

### 3.1 输出有效几何

检查有限数值、合法索引、非退化三角面、正确绕序、归一化法线和有效 UV。平面上的多个三角面保持一致法线；只有真正的形体转折才承担分面明暗。

现有基础图元的多边形面使用扇形三角化。复用时应确认输入面的形状适合该方法；复杂凹面、任意生物拓扑或非平面多边形应使用正确的三角化过程，不能把函数可调用当作结果必然正确。

非均匀缩放不仅改变顶点，也会影响法线。按逆转置关系处理法线并重新归一化；不要只把模型压矮而保留旧法线。

### 3.2 S3O 的静态转角

当前 S3O piece 结构没有独立的静态旋转字段。M1A1 将履带节的初始姿态烘焙进局部顶点和法线，动画控制器再依据生成的初始角度计算运动。

新单位若使用相似方式，几何、法线、初始角度、节点偏移和脚本轴约定必须一起匹配。只改 piece 位置或只旋转顶点会造成运动方向或光照错误。

## 4. 贴图与材质通道

以下描述的是**本项目当前 S3O 链路**，不是通用 PBR 贴图打包标准。来源为[M1A1 图集生成](../../tools/build_m1a1.py#L68-L88)、[原生通道说明](../../tools/build_ztz99a.py#L120-L128)与[资产测试](../../tools/test_m1a1.py#L149-L180)。

| 文件／通道 | 当前语义 | 注意点 |
| --- | --- | --- |
| 第一张贴图 RGB | 表面基础颜色 | 保留平涂色块；不把参考照片直接贴上去 |
| 第一张贴图 A | 队色混合遮罩 | M1A1 主体为 0，队色区为 255；它不是主体透明度 |
| 第二张贴图 R | 自发光 | M1A1 为 0；灯的浅色不代表已做自发光 |
| 第二张贴图 G | 反射／高光控制 | M1A1 对不同色块给出有限差异，不是 PBR roughness |
| 第二张贴图 B | 当前生成器写 0，未用于该案例 | 不擅自当作法线、金属度或其他新契约 |
| 第二张贴图 A | 可见性遮罩 | 主体为 255，战术贴花背景可以为 0 |

M1A1 原生反射值主要是主体 12、橡胶 6、玻璃和钢色 35，取值范围 0–255。它们是当前案例参数；新材质应在引擎光照下检查，不把它们当成所有单位的唯一正确值。

### 4.1 交换 GLB 不是原生材质的逐通道复制

当前[GLB 导出器](../../tools/build_ztz99a.py#L653-L713)将第一张贴图的 RGB 与第二张贴图的 A 组合成内嵌 PNG，使用 `MASK` 可见性和 0.5 阈值。其单一 PBR 材质设置为 `metallicFactor=0.15`、`roughnessFactor=0.76`、`doubleSided=false`。

因此：

- 不要把第一张贴图的队色 A 直接当作 GLB 透明度，否则主体可能变透明。
- GLB 中可见的队色区域只是贴图颜色，不能据此证明引擎的动态队色已正确。
- 当前 GLB 没有完整复现每个 S3O 反射通道值；两个查看器的光照也会不同。
- 生物的翼膜或薄片需要考虑背面可见性；当前单面材质不能自动保证双面可见。
- 新单位如果需要多种真正不同的材质，不应仅重命名 `painted_armor` 就声称已经实现。

当前 S3O 与 GLB 导出器都会在自己的输出阶段处理 V 坐标。更换建模／导出工具时核对贴图方向，避免额外翻转一次。纯色面可以使用色块中心 UV；图案区域则需要足够边距，检查缩小和 mipmap 后的串色。

## 5. 动画能力边界

### 已有能力

M1A1 当前使用刚性 piece、局部平移／旋转和 Lua 动画。GLB 保留静态分件与枢轴，但不包含已经烘焙可播放的履带、炮塔或后坐动画。单独打开 GLB 不会自动重现游戏动作。

### 生物需要额外证明的能力

当前生成器的数据结构及 GLB 导出实现没有写出皮肤权重、`skins` 或动画片段。这个事实只说明当前工具链的能力，**不等于断言 Recoil 的所有可能接入方式都不支持蒙皮**。

连续皮肤单位应先完成最小形变原型：一个代表性关节、一段运动、实际使用的导出方式和目标引擎加载。确认权重、法线、层级和播放方式以后再全面细化。若采用刚性分节替代，向交付对象明确说明限制；不能把制作格式支持某字段等同于游戏已经支持它。

共享控制器可以复用逻辑，各单位仍应拥有自己的尺寸参数、节点列表和运动状态。由生成器输出的数据从源头修改后重建，不手工改出与模型不一致的副本。

## 6. 可复现构建与保留旧资产

新资产采用独立名称和输出路径。构建前列出将被写入的文件，检查目标是否已有内容；只有当前任务授权重制的资产才可覆盖。风格统一任务不自动授权改动旧单位数值、阵营、寻路或全局配置。

可编辑源和导出资产保持对应。若直接编辑 GLB 但没有同步生成源，要明确哪一个成为权威源，避免下次生成把修改悄悄覆盖。

复用既有工具时检查个案假设：当前基础导出器包含装甲材质默认值和模型包围中心等设置，它并非已完成抽象的通用生物导出框架。新模型应验证自己的包围体和材质，而不是直接沿用坦克常量。

### M1A1 的现有命令

下面命令以 **Recoil 工作区根目录**为当前目录，即包含 [games](../../../../games) 的目录。在 [MyGame.sdd](../..) 内运行时，应相应去掉路径前缀。

仅在需要重建 M1A1 时运行：

```sh
python -I games/MyGame.sdd/tools/build_m1a1.py
```

这会写入 M1A1 模型、贴图、生成参数、统计与预览；需要 Python 3.10+、NumPy、Pillow。`--no-preview` 只跳过预览阶段，仍然会写其他生成资产。游戏正在加载这些文件时先退出对局再重建。

只做规范、风格咨询或审阅时不需要执行构建。固定风格图片位于本目录的 [reference](reference)，不属于生成器输出目录。

## 7. 验证分层

### A. 静态资产检查

检查输出预算与实例计数、节点层级、法线、UV、材质通道、包围体、图标及源／交换／原生模型一致性。M1A1 已有入口：

```sh
python -I games/MyGame.sdd/tools/test_m1a1.py
```

它检验 M1A1 的具体轮数、102 节点和 3,200 面上限；新物种或新机械不能直接套这些断言。

### B. 脚本与运动逻辑检查

```sh
python -I games/MyGame.sdd/tools/test_tracks.py --model m1a1
```

当前 Lua 检查需要 `lupa.lua51`；隔离安装时按现有测试文档追加 `--lua-path`。此入口针对当前支持的履带模型，不能把 `m1a1` 替换成任意生物名字就声称支持该模型。新单位需要自己的运动检查。

### C. 实机检查

```sh
python -I games/MyGame.sdd/tools/smoke_mbt.py --model m1a1 --safe-mode
python -I games/MyGame.sdd/tools/smoke_tracks.py --model m1a1 --safe-mode
```

这些命令会启动并操作真实 Recoil 窗口，不是无界面的静态检查。仅在任务需要并且当前允许时运行，使用隔离配置和日志，结束时只关闭本次启动的客户端。原测试会写入新的临时目录，不应改为操作用户现有对局。

本机已有高频截图造成驱动挂起的记录，因此沿用稀疏截图与日志验证，不默认录制高频图序列或 GIF。人工测试可使用 [Test-M1.bat](../../Test-M1.bat)；环境细节见现有 M1A1 测试文档。

### D. 风格判断

自动检查证明资产结构与指定契约是否一致，不能单独证明美术好看或物种可信。依据通用指南的 G1–G4 进行视觉检查，并区分：

- 离线灰模与材质预览。
- 原生引擎中的实际外观。
- 本次运动测试证据。
- 旧截图或历史测试报告。

只完成 A 不能报告 B／C 通过，旧测试计数也不能当作本次测试数量。

## 8. 最终交付核对

按[任务与交付模板](BRIEF_TEMPLATE.md)列出：权威源、运行资产、交换资产、贴图与通道、节点／形变方案、预览、预算统计、实际执行命令、结果和未验证项。

交付新模型不等于有权限一并修改武器伤害、生命值、阵营或出生链。若接入确实需要关联定义，改动范围单独说明；与造型无关的玩法参数保持原样，除非任务明确包含这些修改。

## 9. 建筑接口与旧模板边界

建筑的视觉、空间和状态要求见[建筑分支](BUILDINGS.md)。以下是 2026-11-10 对现有源码的只读核对，用于定位接口，不是建筑已经通过运行测试或 M1A1 风格验收的证明。

### 9.1 分别读取占地、通道和产出定位

| 项目 | 当前可查实例 | 对新建筑的要求 |
| --- | --- | --- |
| 运行模型与脚本 | [Factory 定义](../../Units/Factory.lua#L5-L12)加载 `Factory1.s3o` 与工厂脚本 | 先核对真正被加载的资产，单改交换 GLB 不代表原生模型已更新 |
| 占地与碰撞 | [Factory 尺寸](../../Units/Factory.lua#L29-L59)分别配置 `FootprintX/Z`、`collisionVolume*` 和 `YardMap` | 三组数据分开核对；不要由几何缩放推断它们自动改变 |
| 生产定位 | [QueryBuildInfo](../../Scripts/factoryscript.lua#L21-L23)返回 `BuildSpot` | 将脚本、模型节点、局部坐标与最大计划生产单位对齐，再测试实际产出位置 |
| 门与通行状态 | [Open／Close](../../Scripts/factoryscript.lua#L25-L43)移动 `Wall1/Wall2`，并设置 `COB.YARD_OPEN` 等状态 | 可视门动画与通行状态都需验证，不以有门洞替代连续离厂测试 |
| 建造特效定位 | [QueryNanoPiece](../../Scripts/factoryscript.lua#L45-L55)在 `Flare1`–`Flare4` 中选择 | 节点只是特定脚本的定位契约，不要求所有建筑沿用相同名称与数量 |

Factory 当前 `FootprintX/Z` 为 12 × 10，`YardMap` 文本是十行、每行十二个字符。这仅是该实例的数据对应，不是所有工厂的默认占地，也不说明任意尺寸的坦克已能驶出。字符语义、朝向映射和引擎网格换算按实际链路核实，本指南不凭字符外形推断。

### 9.2 有回调不等于有完整状态实现

- [工厂 Activate／Deactivate](../../Scripts/factoryscript.lua#L56-L64)启动门的开合线程；[StartBuilding／StopBuilding](../../Scripts/factoryscript.lua#L66-L72)函数体为空。不能据此宣称已经有完整施工进度或生产动作表现。
- [采集器定义](../../Units/Extractor.lua#L25-L48)包含采集、开关与占地字段；[采集脚本](../../Scripts/extractorscript.lua#L8-L33)在激活时旋转 `Stem`、停用时停止，而 `ExtractionRateChanged` 为空。现有旋转不自动证明产量驱动的可视反馈已实现。
- [能源脚本](../../Scripts/energyreactorscript.lua#L1-L16)在创建时启动 `EpicEnergyBall` 的上下移动循环；该脚本没有停机回调。不能把这段待机循环描述成已验证的发电／缺能状态机。
- [防御塔定义](../../Units/LLT.lua#L30-L55)与[瞄准脚本](../../Scripts/lltscript.lua#L26-L49)可用于查找武器、转轴与炮口接口；它们不证明换模型后的全角度转向、射击与结构空间仍正确。
- [工厂 corpse 配置](../../Units/Factory.lua#L13)被注释，而[死亡回调](../../Scripts/factoryscript.lua#L75-L84)仍返回 1 或 2。单凭回调返回值不能证明完整残骸资源、阻挡或回收链已经接通。

### 9.3 旧模板需要重验，不直接照抄

例如[能源建筑定义](../../Units/energyreactor.lua#L30-L44)的占地为 3 × 3，`YardMap` 却写成四组四个字符；其尺寸与文本长度不一致。这里记录可直接核对的源码差异，不在未运行引擎时断言解析后会发生哪种行为。新建筑应确认自己的数据对应，不能照抄旧值再以“模板已有”作为通过证据。

同样逐项检查真正的模型、图标、节点、特效和残骸引用。现有 Factory 的[生产列表](../../Units/Factory.lua#L48-L54)不是新美术任务可以默认扩展的范围；为 M1A1 级车辆设计工厂空间，不等于已获准把 M1A1 加入生产列表。

这些旧资产与配置在本次文档任务中保留，不修复、不启用、不重新渲染。建筑需要另外建立针对放置、生产／通行、工作状态和残骸的验证场景；前文的坦克测试命令不覆盖这些行为。
