# Vehicle Factory · 制作契约与验收记录

日期：2026-11-10。当前阶段：**G1 灰模候选**，不是已完成的新工厂验收。供本次建模、脚本、接入与测试共同使用；尺寸候选须经资产测量及灰模核对后固化。

## 1. 目标与边界

将现有 `factory` 重制成平涂块面低模的车辆制造厂。沿用 [通用风格](../UNIT_MODELING_STYLE.md)、[建筑适配](BUILDINGS.md)、[机械适配](MECHANICAL.md) 和 [原生技术流程](RECOIL_PIPELINE.md)。本次不改变全项目风格基准。

- 保留最新生产目录及顺序：`spider → stumpy → flare → duron → scout → m1a1`。后两项来自当前单位定义中的后续改动，不能用早期四项基线覆盖。
- 保留造价、生命值、建造速度、阵营、出生链及任务外单位。仅为新建筑接入修改模型、脚本、图标、必要的空间与碰撞字段。
- 保留旧模型、贴图和脚本；新资产采用独立 `vehicle_factory` 前缀。
- 当前原生基线已验证：输入占地 12×10 对应 `xsize/zsize=24/20`、`Game.squareSize=8`，即 **192×160**。旧工厂可以实际生产蜘蛛并正常离厂。新工厂默认保持该占地。

## 2. 视觉方向

**重工业车间 + 可见装配区**，而不是两块会分开的发光外壳。

| 识别锚点 | 形体与用途 |
| --- | --- |
| 宽大的前部车间门 | 有厚度的门框、横移双门与真实侧向门袋，清楚标出出厂方向 |
| 后部高厂房、前部装配区 | 后车间有斜面屋顶；中央装配区保留俯视可见的生产空间 |
| 非对称辅机体积 | 一侧低控制舱，另一侧冷却设备，主次低于厂房与入口 |
| 横跨车间的生产桥架 | 生产时移动的桥架、两只工具头及纳米定位点，均避开产品包络 |
| 屋顶队色与少量警示色 | 宽阔灰白主体、深蓝灰屋顶、石墨机构、低饱和琥珀点缀；顶面队色不依赖正门朝向 |

地基采用低矮承台与接地裙边；行车地面接近原生地面高度，避免完工产品立即陷入高地台。墙面、顶面保持大色块和留白，格栅与标记用宽图案，不堆铆钉、细管或霓虹。

## 3. G1 空间候选

坐标为 X 右、Y 上、Z 向出厂方向。以下是灰模候选值，后续以通过检查的生成参数为准。

| 项 | 候选 |
| --- | --- |
| 总占地 | 12×10；192×160 世界单位 |
| 地基外沿 | X ±94、Z ±78；低裙边可下沉约 3–4 单位 |
| 中央通行空间 | X ±46；后壁约 Z=-72，门平面 Z=52，门前路面延续至约 Z=78 |
| 门洞净高 | 至少 52，按实际最大产品与工具扫掠再核对 |
| 双门 | 每扇宽 46，闭门中心 X=±23；打开后各向外移动 48，进入侧门袋 |
| 生产点 | `BuildSpot` 约 (0,0.12,-8)；当前目录产品应在可见装配区内 |
| 桥架 | 约 Y=62，沿 Z 小幅移动；工具头完整行程的最低点不低于约 Y=48 |
| 屋顶与辅助体积 | 后厂房约 Y=60–64；辅机舱更低；少量排气结构总高约 78–82 |

先用当前六种产品的真实有效姿态检查门与内腔。M1A1 已在最新生产目录内，既作比例对照，也必须作为实际产品验证；scout 同样纳入。蜘蛛的有效姿态来自其生成器的外张姿态，不能用未摆腿的交换树代替。早期 R=40 的保守代理只覆盖前四项，不能用它宣称 M1A1 长炮管或新增产品的全姿态已经通过；补充包络与出厂检查在 G1/G4 中分别记录。

门袋须有实际侧向空腔。可动门板不能穿过未留槽的实体门框；中央产出点至出口保持连续，无装饰柱、工作机构或厚地台挡路。最终 YardMap 与门的开关状态、后壁方向分别验证。

### 已测空间与运行边界

主线程已执行独立资产测试：当前六种产品的闲置、朝前直线出厂几何检查通过，原四种产品的保守运动代理和 Scout 运动检查也通过。M1A1 任意全车转向与无限制炮管俯仰的保守代理为 **R=71.310058、最高 Y=77.110057**，超出本厂 92 宽／52.38 高的门洞；该额外姿态检查实际为 **FAIL**，不能被 R40 或普通出厂通过替代。

本轮空间契约是正常生产姿态及原生实际离厂轨迹，不保证车辆在厂内任意旋炮、大仰角开火。新厂原生测试仍须确认真实出厂过程不会进入导致穿插的姿态；若正常离厂出现穿插，继续修改建筑，不能用传送、改坦克脚本或放宽结果来掩盖。极端厂内武器姿态作为明确限制保留，不宣称已支持。

## 4. 文件与 piece 接口

权威源拟为 [build_vehicle_factory.py](../../tools/build_vehicle_factory.py)。新产物使用：

- 模型：`Objects3d/vehicle_factory.s3o`、`Objects3d/vehicle_factory.glb`。
- 贴图：`UnitTextures/vehicle_factory_diffuse.tga`、`UnitTextures/vehicle_factory_material.tga`。
- 图标：`UnitPics/vehicle_factory.png`。
- 参数：`Scripts/vehicle_factory_data.lua`；只从生成源重建。
- 动作脚本：`Scripts/vehicle_factoryscript.lua`。
- 预览与统计：`tools/previews/vehicle_factory/`，灰模、最终图与原生证据分目录保存。

拟定 12 个节点：

```text
Base
├─ DoorL
├─ DoorR
├─ Gantry
│  ├─ HeadL ─ NanoL
│  └─ HeadR ─ NanoR
├─ FanL
├─ FanR
├─ WorkLamp
└─ BuildSpot
```

`NanoL/NanoR/BuildSpot` 为空定位节点。主体与固定设备合并在 Base，门、桥架、工具头和风扇按独立运动分件。灯的壳体在固定几何中，WorkLamp 是单独光面，不与另一个同位置光面重叠。

建议最终实例预算 3,000–4,500 三角面，6,000 为本次审查上限而非项目硬限制；灰模无需填满预算。使用单材质、两张 256 或 512 图集，尺寸按图案与边距决定。包围体包括开门、桥架、工具头和旋转风扇的完整运动包络。

## 5. 状态与通过条件

- **G1**：灰模多视图、当前最大产品、M1A1 同场比例与门袋完整行程通过；未通过时只改结构，不进入细节。
- **G2**：完成平涂色块、屋顶家族特征、正常 RTS 视距及成组辨识；保持 1–2 个主焦点。
- **G3**：原生／交换／源几何一致，UV、法线、实例预算与状态包围体通过；开门到位再放行建造，取消／重启不遗留门或机构线程。闲置、工作与停止状态有明确表现。
- **G4**：四朝向真实生产当前目录，完整出厂并到达集结点；验证连续生产、不同集结方向、临时拥堵解除、邻接建筑和蜘蛛实际建成工厂。使用原生生产和正常寻路，不传送产品出厂。

本次使用引擎原生建造显示；死亡沿用现有爆炸与消失链，不新增可回收残骸或升级玩法。缺能是否暂停工作机构按实际生产进度信号核对，不把循环动作当作已消耗资源。
