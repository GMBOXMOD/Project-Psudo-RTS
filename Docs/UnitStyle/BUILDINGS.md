# RTS 建筑建模适配

本分支与[通用风格指南](../UNIT_MODELING_STYLE.md)共同使用，适用于基地、兵营、工厂、经济与科技设施、防御建筑、城墙／大门、部署式设施，以及生物巢穴等建筑。

**定位：建筑是可读的游戏设施，不是放大的坦克，也不是孤立的建筑效果图。** 延续 M1A1 的结构可信、平涂大块面和克制细节，同时让玩家读懂建筑职能、占地、入口和当前状态。

本分支于 2026-11-10 补齐并接入 v1 标准。以下建筑方案、预算和状态设计是迁移建议；项目现有建筑资源不因此自动成为通过此标准验收的标杆。建筑的材质、分件和实际接入另读[Recoil 技术流程](RECOIL_PIPELINE.md)；带活动机械时补读[机械分支](MECHANICAL.md)，活体建筑补读[生物分支](ORGANIC.md)。

## 1. 从 RTS 职能确定识别锚点

先写明这栋建筑“提供什么、怎样工作、哪里与单位交互”。通常选 3–5 个能在正常俯视角读到的锚点，用主形体表达，而不是靠小文字、悬浮图标或特效补足所有信息。

| 建筑类别 | 优先表达的形体与功能 | 需要预留的交互空间 |
| --- | --- | --- |
| 指挥／主基地 | 主体规模、稳定基座、指挥／通信核心和阵营主标识 | 若承担生产或交付，预留对应入口与出口 |
| 兵营／步兵生产 | 成组的低矮房体、明显门厅或训练／集结区 | 人形出入口及门前集结空间 |
| 车辆工厂／重工业 | 大跨度厂房、车间入口、少量工作机构 | 最大计划生产单位的产出位置、出口和离厂路线 |
| 采矿／资源采集 | 采集头、钻架、收集腔或资源接口 | 资源点对位；若有运输单位，保留装卸通道 |
| 能源／发电 | 反应核心、宽散热区、成组储能体或有辨识度的叶片 | 只预留玩法真正需要的维护／连接空间 |
| 仓储／物流 | 仓体、罐体、堆放模块与装卸口 | 装卸、掉头或运输路径，按实际玩法确定 |
| 科技／雷达／支援 | 研究核心、天线／碟面、设备舱等少量焦点 | 确有交互时预留接口，不能只加同一种雷达充当所有职能 |
| 炮塔／防空／防御堡 | 基座、射击主体、武器方向与瞄准空间 | 炮口、俯仰／旋转扫掠区，必要时保留驻防入口 |
| 城墙／闸门 | 连续防线、端柱、转角、清楚的通行缺口 | 关门阻挡与开门通道，含相邻墙段衔接 |
| 生物巢穴／孵化设施 | 扎根或附着基部、主体腔室、孵化／排出口 | 生物出入口、组织活动范围及实际需要的通道 |

表中形体是设计方向，不要求为尚不存在的玩法制造“看起来可交互”的假接口。同一阵营可以共用构造语言，但不同职能仍需有明显的大轮廓差别；科技级别变化也不只靠多一条细灯带。

## 2. 建筑体积的四个层次

### 2.1 地基：解释接地与占地

用简洁底座、裙边、承台、支脚或生物根盘说明建筑如何落地。地基可以比主体稍宽，但不是用一块过大的装饰平台把周围可通行地面全部占满。

### 2.2 主体：建立身份与容量

厂房、塔身、罐体、巢体等主形体决定这是什么建筑。根据承重与功能组织截面变化、斜面和体块关系，保留宽阔安静的墙面与顶面。不能只搭一个没有主次的方盒，也不需要把每一层楼和每一根承重杆都独立建模。

### 2.3 功能结构：让工作方式可读

入口、主武器、散热单元、吊臂、钻头、孵化口等作为二级形体。几何投入优先给其轮廓、深度和活动空间。外露管路归并成少量明确的走向，不铺满墙壁。

### 2.4 识别点缀：保留少数焦点

舱门色带、阵营标记、观察窗、状态灯、少数紧固结构提供尺度与识别。它们应依附于主结构，不成为满屋碎格、细杆和发光线。屋顶也应有安静区，不能因为俯视看得见就塞满设备。

## 3. 俯视可读性与基地组合

### 3.1 顶部不是可以省略的背面

在常用 RTS 俯视角，屋顶、上部轮廓和地基往往比正立面更重要：

- 顶部至少有能支持职能识别的形体关系，例如工厂屋顶与大门方向、反应器核心、炮塔与底座。
- 队色或阵营标记放在实际看得到的上表面／宽侧带；不要只放在贴近地面的细门牌上。
- 检查任务允许的摆放朝向。建筑转到背面或相邻房体遮住正门后，仍应读得出类别；不要求每个朝向都能看到同一个入口。
- 冷却塔、通信杆、翼面或高塔可以很高，但要检查相机下对附近单位、建造点和选区的遮挡。轮廓锚点应有收益，而不是无理由拔高。

### 3.2 单体与成组两次检查

先将建筑单独与 M1A1 放在正确的实际比例下，随后检查一组基地布局：生产、经济、科技、防御建筑混排，并放入真实大小的单位。

远看检查功能与阵营，正常视距检查出口、主要活动和颜色焦点，近看检查穿插、门框厚度和贴图边缘。相近占屏比例的风格对照用于比较细节密度，不用于把工厂缩成坦克大小。

让重复建筑形成秩序，避免每栋都用同样强的塔尖、霓虹或浓烟争夺注意力。装饰性附属物的对比低于主功能区；基地密集时仍应读清单位与行走通道。

## 4. 尺度、占地与出口必须分别成立

### 4.1 区分四种范围

| 范围 | 说明 | 不能混为一谈的内容 |
| --- | --- | --- |
| 视觉范围 | 模型及正常活动部件实际看得到的范围 | 不能单凭宽地台暗示整片区域都被阻挡 |
| 建造占地 | 引擎允许放置建筑时占据的格子或地块 | 不由模型缩放自动替代其配置 |
| 碰撞／阻挡／选择范围 | 引擎用来碰撞、寻路阻挡和选取的定义 | 各系统可能使用不同数据，需分别验证 |
| 交互与活动范围 | 生产点、出口、装卸、开门和武器扫掠需要的空间 | 不等于静止状态下的包围盒 |

记录各自来源和待验证项。具体网格大小、占地字段及通道规则从项目和引擎读取，不假定一格等于某个固定米数，也不把 M1A1 的碰撞盒复制给建筑。

### 4.2 生产建筑的最低空间检查

以**计划生产的最大单位**建立空间原型，使用实际比例检查：

1. 内部产出位置是否正确，建筑主体是否把新单位包在不该穿过的墙体里。
2. 门宽、门高、门框厚度、打开后的门板和屋檐是否给车体、武器与附肢留出余量。
3. 产出点到出口是否连通，出口到门前通道是否连通；不能只检查门洞处。
4. 多次连续生产、集结点改变、相邻建筑和城墙是否让离厂路线堵塞。
5. 门开合、生产动画与放行时机是否一致，停止生产后是否留下错误的阻挡状态。

先做空间灰模，再做复杂大门或内部机械。只为视觉做了一个洞，不代表配置上已经能走出去；模型与实际通行测试需要分别完成。仅方案任务写出这些验证计划，不擅自修改生产目录或寻路规则。

不需要显示内部的建筑可用简化内壁和受控暗面封闭开口；没有内部交互需求时省去完整室内。会让单位出入或相机看到里面的门洞，不能用一块无厚度的黑平面假装已解决空间关系。

## 5. 地基、地形与模块拼接

- 在平地检查无明显悬浮、漏底、穿地和贴地面闪烁；地面装饰与主底座保持合理关系。
- 坡地处理服从玩法允许的摆放与地形适配方式。模型裙边只能遮盖合理的细小接缝，不能把大幅悬空伪装成已经支持任意斜坡。
- 水上、悬空、悬崖或地下建筑单独定义支撑／连接方式；只有任务需要时才增加对应资产和检查。
- 对城墙、地台、管线等模块，统一可拼接的端面、宽度、基准高度、局部原点和合法朝向。
- 验证直线、转角、端头和大门连接；不能只看一块墙段单独摆着。允许的地形高差是否需要阶梯段、填缝段或放置限制，应先确定。
- 模块接缝避免共面重叠、明显漏光和重复装饰堆积；连续复制后检查色块节奏和总显示成本。

装饰地台、屋檐或活动门板可以超出主体占地，但必须检查相邻放置、角色通行、选取和遮挡，而不是默认超出部分完全没有影响。

## 6. 同阵营建筑的家族语言

用少量稳定要素统一系列：主材质、屋顶或壳体截面、边缘处理、门框比例、支架／根系形状、队色位置和标识设计。

在此基础上用主轮廓、主体高低关系、功能装置和入口方向区分职能。基础设施、重工业与高级科技建筑可以逐级增加层次，但升级不等于均匀加一圈小盒子和细管。

共用模块适合墙面、门框、底座、散热块等次要构件。主功能体积仍按建筑身份设计；同一套零件反复组合后若所有建筑都像同一个集装箱，应先调整主形体而不是再加装饰。

共用资产的修改会影响所有引用者。扩展某一栋建筑时，先区分实例特例与家族模块变更；后者需要检查相关建筑，而不是只看当前对象。

## 7. 材质、图案与队色

沿用通用指南的语义色块与哑光主体。建筑可以有涂装金属、混凝土、石材、木材、玻璃、甲壳或软组织；材质身份主要由色区、结构厚度和少量受控反射共同说明，不默认依赖照片或复杂 PBR 表皮。

- 混凝土／石材保留宽面和必要接缝，砌块节奏可以概括为大分区，不逐砖刻满。
- 金属板缝、百叶、窗和冷却栅格优先归纳成少量宽带；远看消失的细分不值得遍布全楼。
- 队色服务于阵营识别，少量状态色服务于工作／停机等提示；不要让两者互相覆盖，也不要只靠颜色区别建筑类别。
- 建造预览的有效／无效着色、选中反馈和战争迷雾显示属于引擎／玩法呈现。为这些状态预留可读轮廓，不把临时颜色或透明度永久画入基础贴图。
- S3O 的队色遮罩与可见性遮罩不是同一个通道；透明窗、网架、贴花或活体薄膜按技术分支核对。用大面积透明壳体遮掩内部未制作不是默认方案。
- 标志、屋顶灯和工作特效保持焦点，不让整片基地成为互相遮挡的亮线、粒子和烟幕。

## 8. 建筑预算与复用成本

以下为**新增建筑原型的建议起点**，并非现有建筑实测结果、引擎保证或用户已指定的上限。实际预算取决于占屏尺寸、同屏数量、运动结构和状态复用；明确任务预算优先。

| 类别 | 最终三角面建议起点 | 优先投入 |
| --- | --- | --- |
| 重复墙段、小型附属模块 | 100–600 | 拼接轮廓、顶缘和必要厚度 |
| 小型炮塔、采集器等设施 | 800–2,000 | 功能主体、基座和活动部位 |
| 中型兵营、电站、仓库 | 1,500–3,500 | 主轮廓、顶部职能特征、入口 |
| 大型工厂、指挥设施、孵化巢 | 2,500–6,000 | 大体积关系、生产空间、少量关键机构 |

不为达到下限填面，也不为守住建议数字切掉出口空间或关键结构。超出区间时解释新增几何的收益，并用实际基地规模检查成本。

记录整栋建筑的实例三角面、导出顶点、节点／骨骼、材质、纹理、透明叠层和特效。模块实例重复出现时全部计入；同时统计一段城墙或一组基地，不能只报一个去重模块有多少面。

状态共用几何时，区分资源总量与**同一时刻实际显示的最大组合**，例如主体加施工脚手架或主体加受损附件。LOD、批处理、动态隐藏或资源复用只有在目标链路确实支持并验证后才算优化，不能仅凭存在多个文件就宣称已生效。

简单平涂图集可从 256 × 256 或 512 × 512 方案比较；尺寸与材质槽按图案和显示需要调整，不因为建筑大就默认整套高分辨率贴图。大面需要的是正确色块和结构，不是填满微小纹理。

## 9. 建筑状态与动画

### 9.1 先列状态，再选择表示方式

下面是应考虑的状态目录，不要求每栋建筑都提供所有功能，也不要求每种状态制作独立整模。将任务需要、已有支持、计划实现和不适用项分开记录。

| 状态 | 美术应当表达 | 接入前要核对 |
| --- | --- | --- |
| 放置／建造预览 | 轮廓、朝向、占地和出口方向 | 引擎预览、有效区域与临时着色方式 |
| 建造中 | 有根据的完成进度、结构顺序或脚手架 | 建造进度来源、显示方法和阻挡规则 |
| 完工待机 | 完整建筑身份、入口和阵营 | 静止模型、默认部件可见性 |
| 工作／生产 | 少量明确机构动作或局部指示 | 工作事件、生产点、放行及停止事件 |
| 停用／缺能 | 与工作状态有可读差别 | 玩法是否支持该状态，状态信号来自哪里 |
| 受损／修复 | 适度破损、局部附件或控制范围的特效 | 触发与恢复条件、是否影响通路与功能 |
| 摧毁／残骸 | 可辨认残留体积或消失过程 | 独立残骸资产、可回收／阻挡等实际规则 |
| 升级／展开／收拢 | 原有身份与新状态的轮廓关系 | 是否改变占地、碰撞、出入口和可动范围 |

施工时不默认让整个已完成建筑从小号均匀缩放长大；可优先考虑项目支持的分件显隐、施工框架或引擎原生建造显示。若当前玩法只有静态完工模型，交付时写清缺少哪些状态，不能把方案表当作已实现功能。

受损和残骸仍服从大形体与克制细节，不把整栋打碎成大量微小垃圾。破坏表现是否改变阻挡或资源回收由玩法决定，不能因为模型消失就默认通路已经打开。

### 9.2 固定结构稳定，机构按功能运动

建筑主体默认稳定地落在基座上。炮塔、吊臂、门、雷达、泵或钻头围绕自己的枢轴工作；起动、停机、开合和攻击都有触发原因，而不是全楼无缘由地周期摇摆。

门按真实厚度和扫掠范围检查。旋转炮塔检查全角度与俯仰下的结构干涉、炮口位置和附近建筑；采集、生产或装卸动画检查工作位置，而不只看循环是否流畅。

烟、光、粒子和声音若属于任务范围，围绕功能节点组织；效果资源和事件驱动未接入时，不把静态模型上的烟囱、灯或骨骼节点当作已有功能。

## 10. 生物建筑与混合建筑

活体建筑先满足建筑分支的职能、占地、入口和状态要求，再使用生物分支表达组织、甲壳、根系、呼吸与形变。

- 基部通过根盘、腹侧或支撑组织解释扎根与重量；主体通过壳腔、孵化室和开口形成清楚体积。
- 甲壳是硬质结构，软囊或开口可以局部活动；不把整栋巢穴一律做成装甲盒，也不要求整栋都使用连续蒙皮。
- 呼吸和脉动局限在合理组织并有轻重层级。主体、出口和接地不能随无意义的大幅起伏造成明显穿插或误导通行。
- 需要软组织连续形变时，先验证当前导出与播放链路。静态 GLB 或刚性 piece 的存在不等于蒙皮、孵化或生长动画已实现。
- 混合建筑的机械设备与活体组织各自有材质和运动逻辑，但共享大块面尺度与低噪声表面。

## 11. 两个制作方案示例

**计划生产 M1A1 级车辆的工厂**：宽低车间为主体，单侧辅机舱构成次级体积，大门和屋顶散热区形成识别锚点。先将真实大小的 M1A1 放入空间灰模，确认产出点、门洞、门板扫掠和门前路线；再补少量队色、结构暗面与机构。是否把 M1A1 加入生产目录属于另外的玩法接入改动，不能因这个美术方案自动发生。

**四足生物的孵化巢**：稳定根盘、大壳腔、低位孵化口和少量背部组织构成主形。以计划产出的最大生物检查开口和活动空间；壳片保持大面，软组织只在必要部位形变，队色由宽阔壳区或天然斑纹承担。生产、呼吸、建造和残骸逐项记录实际支持状态。

两者都是迁移示例，不是已制作模型或已运行的测试结果。

## 12. 建筑验收与交付补充

沿用通用指南 G1–G4，每项填写 `PASS / FAIL / NOT_RUN / N/A（原因）`。这里只列建筑增加的检查，不能代替通用验收。

### G1 · 职能、尺度与空间

- [ ] 常用俯视角与允许摆放朝向能读出职能、主体与主要交互方向。
- [ ] 与实际大小的单位同场检查过比例；视觉范围、建造占地和关键空间有记录。
- [ ] 生产／通行建筑的最大单位空间原型成立，或明确列为待验证。
- [ ] 成组摆放时职能差异、单位识别和通道留白仍清楚。

### G2 · 家族风格与表面

- [ ] 地基、主体、功能结构、点缀有层级，屋顶没有变成设备噪声。
- [ ] 模块的比例、边缘处理和材质职责统一，但不同建筑不只是换颜色。
- [ ] 队色在实际视角可读，临时状态效果没有被烘进基础贴图。
- [ ] 整栋及典型重复组合的预算已统计，状态同时显示的峰值有说明。

### G3 · 结构、地形与状态

- [ ] 地面接缝、底面、模块端头和允许的地形条件下没有明显穿帮。
- [ ] 门、生产机构、炮塔等在完整运动范围内没有明显干涉。
- [ ] 建造、完工、工作、停用、受损、残骸及升级逐项说明支持／缺省／不适用状态。
- [ ] 定位节点、层级和相关配置经过核对；活体形变链路的限制已注明。

### G4 · 实机功能与交付

- [ ] 目标引擎的放置、朝向、选择、占地与阻挡行为已检查，或标为未运行。
- [ ] 若承担生产：实际产出和连续离厂已测试，不仅是门洞看起来够大。
- [ ] 若承担采集、能源或防御：实际所需的状态／工作／瞄准事件已验证。
- [ ] 仅有静态模型时没有声称全套状态、通行、生产或残骸已经可用。
- [ ] 交付源文件、需要的状态资产、定位与占地说明、模块约定、预览和实际验证结果。

仅文档或方案任务不运行模型生成、引擎或玩法改动。首栋建筑完成实机与风格验收后，再提议将它补充为建筑基准；旧建筑模板和本节示例都不能提前代替这个步骤。
