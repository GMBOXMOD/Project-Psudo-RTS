## B. 设计与实现

### 识别锚点

1. **六条外张分节腿**，膝盖高过车体，脚掌分布远宽于车身。
2. **低矮宽体 + 高离地间隙**，与两辆坦克的箱形车体区分。
3. **两条前置工程臂**，末端为焊枪头与纳米发射环。
4. **琥珀色传感器**（车头三枚镜片 + 工具头工作灯），在深灰装甲上是唯一暖色焦点。

### 形体与颜色

- 一级：车体、六腿；二级：工程臂、髋/膝关节、脚掌；三级：观察窗、排气、格栅、标记。
- 调色板 14 个语义色：石墨主体三阶、橡胶、钢、黑、琥珀镜片、深琥珀、灯、红、队色、帆布。
- 队色放在**尾甲板水平条带**上——竖面板在 RTS 俯视角看不到。

### 两个关键实现决定

**腿的网格不做斜置。** LUS 的 `Turn()` 只接受 `x/y/z` 三个主轴，传任意轴向量会报 `Turn(): Bad axis`。所以六条腿共用同一份标准网格，外张角由运行时髋关节偏航提供（右腿 `+splay`，左腿 `180°-splay`），膝盖绕**局部 z 轴**弯曲——piece 旋转相对父节点，膝轴会跟着髋一起转。

**停步相位（历史实现，已替换）。** 旧版本只把摆动相的腿拉回 0.5，仍会破坏两组三足的半周期间隔。2026-11-10 已复现一次走停后六腿同时收到抬腿目标；当前改为共享位移相位、固定分组，停步只降低膝关节显示姿态，见 G。

**S3O 头部的包围球按摆姿修正。** 导出的 piece 树是标准姿态，但玩家看到的是外张后的姿态；直接沿用会让包围球偏小。生成器写完 S3O 后回填 radius / height / mid 三个字段。

### 关于“不会建造”（2026-11-10 定案）

现象：纳米粒子持续喷射、命令为 `-8`、`Spring.GetUnitIsBuilding` 返回目标、资源充足，但 `buildProgress` 与血量永远停在初始值 `0.1`。

根因：**单位定义缺 `terraformSpeed`**。

```cpp
// CBuilder::Update
updated = updated || UpdateTerraform(fCommand);   // 先跑，且会 return true
updated = updated || UpdateBuild(fCommand);       // 被 || 短路，永不执行
```

`StartBuild` 对需要平整地基的目标会置 `terraforming = true`，此后 `UpdateTerraform` 每帧执行 `terraformLeft -= terraformSpeed`。

关键在 `terraformSpeed` 的默认值：源码是 `GetFloat("terraformSpeed", buildSpeed)`，也就是**默认等于 `workerTime`（这里 6）**，不是 0。而平整一座建筑地基所需的 `terraformLeft` 远大于这个数（内部还除以 30 换算成每帧量），于是地基平整要花掉远超正常建造时间的一段时间——实测 10 秒内 `buildProgress` 一点不动。这段时间里 `UpdateTerraform` 一直返回 true，`UpdateBuild` 被短路；它自己又无条件喷纳米粒子，于是表现为“看着在造、进度不动”。

给到 `9001` 后地基瞬间平完，`terraforming` 立刻转 false，建造正常开始。

验证方式：同一模型、同一脚本、同一出生点，只改单位定义。

| 定义 | 实测 |
| --- | --- |
| 原 `spider.lua`（无 `terraformSpeed`） | `health 0.1 → 0.1`，`buildProgress 0.0000` |
| `constructor` 定义克隆（含 `terraformSpeed`） | `buildProgress 0.0098 → 0.1073`，速率 = 5/205 |
| 原定义 + 一行 `terraformSpeed = 9001` | `buildProgress 0.0439 → 0.1024` |

修复：`Units/spider.lua` 增加 `terraformSpeed = 9001`（与 `Constructor.lua` 一致），并在 `test_spider.py` 里加断言锁住该字段。

此前两种解释均不成立：`TestBuildOrder` 返回 2 不能说明站点无效（同站点在克隆定义下正常开工）；`COB.INBUILDSTANCE` 未置位也不是原因（最小脚本同样失败，而克隆定义配同一份脚本却能建）。

### 修复依据与实现

1. **走停后失去交替支撑。** 原脚本的最小回放是前进 6 帧、停 2 帧、再进 4 帧，每个移动帧推进 1 个世界单位；两组三足会同时收到抬腿目标。任意一段减少 1 帧即不触发该序列中的失败。长停后相位差也从 0.5 被改为约 0.1667。
2. **转弯时分组漂移。** 六腿各自累积不同的转向相位，曲线行走中出现超过三足抬起。当前使用一个位移驱动的共享相位，腿只保留固定的半周期分组偏移；左右行程及方向改变步幅，不改分组。
3. **步幅与脚底轨迹不匹配。** 旧代码将 18 单位步长与固定 34° 摆角直接组合，直行也有明显前后滑步。当前在足端空间生成前后行程，再用生成源中的膝／足尺寸换算髋角；34° 只作为安全角度上限。转向使用正确符号及脚掌支撑半径，不再只取狭窄车体的髋间距。
4. **启停衔接。** 支撑相占周期 60%，两组三足之间留有双支撑区；停步只降低膝关节显示姿态，不重写相位、不拖动支撑髋。重新起步、改变方向限制关节目标变化，落稳后不再重复提交腿部变换。
5. **工程臂会动但不施工。** 实机对照排除了 MoveCtrl 恢复与该测试站点问题，确认旧脚本漏设 `COB.INBUILDSTANCE`。只补齐开始／停止建造时的置位与清零，没有调整任何建造数值或建筑模板。

修改入口：[步态控制器](../../Scripts/spider_gait.lua)、[单位脚本](../../Scripts/spiderscript.lua)、[绑定参数生成源](../../tools/build_spider.py)、[生成参数](../../Scripts/spider_rig_data.lua)。这次只从生成源重写绑定参数；生成参数不能脱离源文件手改。
