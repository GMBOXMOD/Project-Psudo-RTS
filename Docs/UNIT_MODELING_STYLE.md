# RTS 单位与建筑建模风格指南：M1A1 基准 · 平涂块面低模

版本：**v1 · 2026-11-09**（建筑分支补充：2026-11-10）  
适用范围：本项目后续的机械、生物、机械／生物混合单位及 RTS 建筑；包括新建、重制、配色、材质、动画／状态表现和风格验收。

> **结构可信，轮廓优先；用干净的大块面和克制的色块表达对象，把细节预算花在辨识、功能和运动上。**

这里的“同一种风格”指同一套视觉表达方法，不是让所有对象都长得像坦克。机械保留机械结构，生物保留解剖和生命感，建筑保留职能、空间和建造逻辑；三者共享块面尺度、细节密度、材质克制程度与游戏视距下的可读性。

## 1. 标准来源与适用边界

### 1.1 哪些是事实，哪些是新规则

- **基准事实**：当前 M1A1 具有低矮而可辨认的轮廓、硬边大块面、沙色平涂、简化设备、低边数轮子和可运动分件。具体数值、源文件和固定图片见基准档案。
- **通用标准**：本文把上述作品的表达方法提炼成以后单位共用的规则。它不声称用户逐条指定过本文每个术语或数值。
- **适配建议**：生物与建筑分支、其他尺寸对象的预算和原型方案是迁移方法；尚未建立经过本指南验收的生物或建筑标杆，不把建议、旧模板或方案示例描述成已经完成的同风格案例。

最新任务若明确要求不同配色、比例或风格，按该任务执行，并在交付中说明与 v1 的差异。单个单位的例外不自动改写整个项目的标准。

### 1.2 保留表达方法，不复制对象属性

| 应当沿用 | 应由新单位自己决定 |
| --- | --- |
| 轮廓与识别特征先于装饰 | 物种、车型、建筑职能、角色、体型和时代 |
| 大、中、小形体有清楚主次 | 长宽高比例、肢体数量、装甲或建筑空间布局 |
| 少量有意义的平涂色块 | 沙色、绿色、兽皮色、甲壳色、建材色、阵营色 |
| 可见块面与克制的反射 | 硬壳、皮肤、橡胶、骨角、涂装与建材等不同材质的表达 |
| 运动能解释功能、支撑和重量 | 履带、足步、扑翼、呼吸、开门、生产或采集等方式 |
| 在正常 RTS 视距下仍可读 | 每类对象的三角面数、纹理尺寸、分件与形变方案 |

M1A1 的七对负重轮、八边形轮子、102 个节点、3,200 面生成上限和沙色调色板都不是其他单位或建筑的硬性要求。

## 2. 先定义“像什么”，再决定“省什么”

### 2.1 分开使用结构参考与风格参考

1. 用结构参考确定类别、比例、功能和运动方式。真实对象优先使用多视图；虚构生物先定义可信的骨架与支撑关系。
2. 用 M1A1 基准确定简化程度、块面尺度、色块组织和细节克制程度。
3. 记录参考缺口和当前假设。缺少某一侧参考时可以合理补全，但不能把推测称为精确复原。
4. 参考图片用于分析，不直接当作模型贴图；外部模型或素材只有在任务许可且许可条件明确时才进入交付。

### 2.2 写出识别锚点

制作前通常选出 **3–5 个识别锚点**，并写清各自主要依赖轮廓、体积、色块还是运动。简单对象可以更少，不能为凑数加装饰。

- M1A1：低矮车体、楔形炮塔与长尾舱、带抽烟装置的长炮管、七对负重轮与侧裙。
- 机械步行单位：腿的支撑方式、躯干／驾驶舱比例、主装备形状、关节布局。
- 兽类：头颈比例、肩背线、骨盆和腿的关系、足型、尾巴或角的特征。
- 虫类：头胸腹关系、足的数量与节律、甲壳外轮廓、口器或背甲特征。
- 建筑：地基与主体、顶部职能结构、主要出入口、工作装置与阵营家族特征。

锚点要能在去掉名称、精细贴图和特效后仍起作用。若只有涂装能区分两个不同角色，先改轮廓或主形体。

## 3. 比例与轮廓

### 3.1 先做灰模

先完成主要体积和可动部位，只使用中性灰或少量诊断色。至少检查前、侧、顶和常用游戏俯视角，再进入小零件或纹理。

- **外轮廓**说明对象类别、朝向，以及怎样移动或工作。
- **内部体积**说明头／躯干、车体／炮塔、胸／腹或建筑主辅体之间的关系。
- **负空间**说明腿间、轮间、翅膀下、工具开口和建筑通道等关键空隙；远看不能全部粘成一团。
- **重心与支撑**说明哪里承重、哪里接地；肢体、支架与建筑地基都有可信的受力或支撑关系。

比例可以为了游戏识别适度强化，例如增大可辨识的角、加粗容易闪烁的炮管或足部。强化只服务于角色与视距，不默认做成大头短身、玩具比例或工程级复刻。

### 3.2 两种尺度对照都要有

- **同一游戏场景中的真实相对尺寸**：检查新单位和既有单位是否处于合理的体量关系。
- **相近屏幕占比下的风格对照**：检查新单位是否比 M1A1 密得多、碎得多、亮得多。

不要为了“看起来统一”把坦克、小动物和巨兽全部缩放成同样的实际体积。

## 4. 块面与法线

### 4.1 面的方向要解释形体

每个主要平面都应当解释装甲转折、骨架方向、肌肉体积或甲壳结构。优先建立宽阔、连续、朝向明确的面，再用少量过渡面连接。

- 机械：用楔体、截面变化、斜面和有限倒角表达结构，不把整台设备简化成几只互相穿插的方盒。
- 生物：沿头骨、肩胛、胸腔、骨盆和肢体轴线安排切面，让面流跟着体积走，而不是沿全身随机切三角形。
- 建筑：按承载与空间关系组织底座、墙体、顶面和功能结构，大面积表面保持有意的留白，不用密集小盒子填满屋顶。
- 同一平面为了导出而三角化时，保持一致法线；不要让一块平板因为三角化变成明暗拼图。
- 低边数圆柱、锥体、椭圆截面和截面放样都可以使用；边数由轮廓与运动需要决定。

### 4.2 硬边是表达方式，不是裂面

M1A1 默认采用逐面法线，分面由光照与体积自然显现。新模型也以明确分面为基调，同时保证面朝向正确、接缝闭合、法线归一化。

生物关节的连续形变可以需要更合理的拓扑或局部柔和的法线过渡；只有在不破坏整体块面语言、且目标导出链能保留该效果时采用。视觉风格与几何是否连续是两回事，不能为制造硬边把皮肤拆出可见裂缝。

倒角只用于确实影响轮廓、体积转折或关键高光的边。大规模细倒角、细分曲面和全表面锐化不是本风格的默认起点。

## 5. 细节层级与取舍

| 层级 | 承担的任务 | 机械例子 | 生物例子 | 建筑例子 |
| --- | --- | --- | --- | --- |
| 一级：主形体 | 一眼辨认类别、朝向、体量 | 车体、炮塔、机身、主腿架 | 头、胸腹、肩背、骨盆、四肢 | 地基、厂房、塔身、主要壳腔 |
| 二级：功能特征 | 解释结构、角色和运动 | 炮管、轮组、侧裙、喷口、抓具 | 口鼻、角、翅膀、足爪、尾、主要甲壳 | 大门、采集头、武器平台、孵化口 |
| 三级：识别点缀 | 少量焦点和尺度提示 | 舱盖、观察窗、粗格栅、单个大标记 | 眼、鼻、少量牙齿、斑块、耳缘、毛簇 | 阵营标记、宽窗带、少量灯和设备 |

一级和二级形体应承担主要识别工作。第三级保持稀疏，给大面留出视觉安静区。

### 5.1 每个细节只走一条必要路径

- 改变关键轮廓、形成明显体积，或需要独立运动：使用几何。
- 只改变表面颜色或浅层图案：使用色块／贴图；例如少量通风槽、条纹、战术标记。
- 只在极近距离才看得见，又不参与角色识别：先省略。
- 虽然很小但属于识别锚点：可有限放大、合并或增加对比，然后回到正常视距检查。

重复部件保留节奏，不追求每个机械微件或每片鳞片。履带节可以简化为粗块，甲壳可以合并成大板，毛发可以归纳成少量成组的形体。

### 5.2 过密时的删减顺序

先删微小装饰和重复细缝，再合并功能相同的小部件，随后减少不改变轮廓的细分；最后才调整关键轮廓。关节活动余量、主装备轮廓、物种锚点和必要的接触面不应最先被牺牲。

## 6. 配色、材质与表面

### 6.1 先分配颜色职责

调色板按语义命名，而不是按第几个网格命名：主体色、主体的亮／暗变体、结构暗色、功能材质色、识别点缀、队色。

| 颜色职责 | 目标效果 |
| --- | --- |
| 主体与少量同色系变体 | 建立大面积统一感；相邻变体有结构理由 |
| 结构暗色 | 分离轮组、关节、口腔、间隙等结构，不铺满整个表面 |
| 功能材质色 | 区分玻璃、橡胶、骨角、皮肤、甲壳等大类 |
| 高对比点缀 | 把视线引到少数关键位置，如眼、传感器、灯、标记 |
| 队色 | 辅助阵营识别，不冲掉对象本来的体积和材质层级 |

构图初稿可以从“主体／结构次色／点缀约 **70／25／5**”开始，但这是新制定的思考工具，既不是 M1A1 的实测面积，也不是必须满足的百分比。颜色数量同样由职责决定，不为凑满调色板而增加噪点。

### 6.2 平涂不等于全身同一个色

- 用几个宽阔、可解释的色区组织体积；照明仍由几何和实际光照承担。
- 同一主体面保持干净，不随机给每个三角面换一种颜色来模拟低模。
- 允许少量宽条纹、斑块和自然的腹背色差；迷彩或斑纹也应服从大尺度图案，而非高频噪声。
- 表面老化若有叙事必要，采用少量大尺度变化；不默认铺照片、毛孔、密集划痕、锈斑或强烘焙阴影。
- 不把深阴影与镜面高光画死在每张贴图上，避免转动单位后仍保留错误光向。

### 6.3 哑光为主，差异克制

主体涂装、皮肤和甲壳以稳定的色块、体积和柔和反射为主。玻璃、金属、角质或湿润器官可以有局部差异，但不能依赖满身镜面、强烈泛光或闪烁细节才能读懂形体。

“克制”不等于把全部材质参数设为一样。M1A1 的 GLB 预览参数和原生 S3O 通道也不是同一材质系统，技术实现见 Recoil 资产流程。换材质系统时保留视觉目标，而不是照抄参数。

## 7. 几何与纹理预算

### 7.1 先确定任务预算，再开始细化

M1A1 是约 3 千三角面的已验证案例，不是万能面数模板。以下仅是移动单位原型的**建议初始区间**，不是用户已指定的硬上限，也不是性能保证；建筑按[建筑分支](UnitStyle/BUILDINGS.md)另行分配单栋、重复模块和状态组合预算：

| 原型类别 | 三角面建议起点 | 预算分配重点 |
| --- | --- | --- |
| 小型、常见、远视距单位 | 800–2,000 | 轮廓、朝向、头／主装备和必要运动部位 |
| 常规车辆、机甲、中型生物 | 1,500–3,500 | 主形体、关节、足轮、身份特征 |
| 大型重装、巨兽、多附肢单位 | 2,500–5,000 | 大轮廓与更多运动结构；先验证同屏成本 |

任务有明确预算时以任务为准。超出建议区间不自动判失败；说明增加的几何服务了什么，并检查屏幕收益、同屏数量、节点更新和材质开销。也不要为达到区间下限而给简单对象填面。

统计口径是最终三角化后**每个可见实例的总数**。多次引用一个轮子网格仍按多个轮子计入总量；同时记录导出后的顶点、节点和材质槽数量。低面数不自动代表低动画成本。

### 7.2 面数按收益分配

优先给外轮廓、弯曲或关节区域、关键附肢和有辨识意义的开口。给被遮挡平面、微型孔洞、重复螺钉或整身鳞片加密，通常收益很低。生物形变需要的环线是功能性预算，不应被当作无用装饰删掉。

简单平涂图集可以从 256 × 256 开始，若图案、UV 间距或实际视距确有需要再扩大。M1A1 使用两张该尺寸原生贴图；其他单位可以不同，不能为了沿用数字而牺牲可读性，也不默认上多张 4K 贴图。

## 8. 动作与重量

共同原则是**动作有因果、支撑可解释、部件与位移同步**，不是所有单位使用同一种动作曲线。

- 机械的旋转、后坐、轮履滚动和关节运动服从功能与受力。
- 生物的步态、重心转移、呼吸、扑翼和尾部跟随服从解剖与运动节律。
- 接触地面的部位尽量有稳定的支撑相；检查滑步、穿地、悬浮和相位跳变。
- 夸张动作服务于角色，避免无来源的整机抖动或所有部件一起摆动。
- M1A1 不额外叠加周期车体弹跳；这个机械案例规则不能用来禁止生物自然起伏。

建筑的固定主体保持稳定，门、生产／采集机构和防御炮塔按功能动作；活体建筑可以有局部呼吸，空间与接地仍需可信。建造、工作、受损、残骸等状态按任务和链路分别验证，不要求所有建筑都制作全套独立模型。

具体分件、步态、建筑状态与适配限制分别见机械、生物、建筑和 Recoil 分支。

## 9. 验收：视觉通过不等于接入通过

检查项记录为 `PASS`、`FAIL`、`NOT_RUN` 或 `N/A（原因）`。未执行的检查保留 `NOT_RUN`，不凭存在一张截图或一份旧报告改成通过。只要求方案的任务可以完成方案交付，但不能称其模型已经通过游戏验收。

所有对象先使用下面的共同检查，再完成所选分支的补充项；建筑追加[建筑 G1–G4](UnitStyle/BUILDINGS.md#12-建筑验收与交付补充)中的职能、占地、地基、出口、状态与成组检查，不能只执行移动单位的动作项目。

### G1 · 灰模与轮廓

- [ ] 不看名称和表面装饰，能读出类别、朝向与核心角色。
- [ ] 所列识别锚点都能在对应视角找到；比例、重心和负空间成立。
- [ ] 前、侧、顶、游戏常用俯视角没有依靠单一漂亮角度隐藏问题。
- [ ] 与既有单位的实际体量关系已核对，或明确标为待核对。

### G2 · 风格与表面

- [ ] 一级、二级形体清楚，细节没有盖过整体。
- [ ] 面的方向服务于结构，平面三角化没有意外明暗缝。
- [ ] 平涂色块有语义，点缀克制；不靠满身微纹理弥补轮廓。
- [ ] 在相近相机、光照和占屏尺度下，与固定 M1A1 基准的细节密度相容。
- [ ] 已检查正常游戏视距；可额外用约 96–128 像素的单位缩略图检查识别。这只是辅助检查，不替代实际视距。

### G3 · 结构与动作

- [ ] 独立运动的部件有正确层级、枢轴或已验证的蒙皮方案。
- [ ] 运动范围内没有明显穿插、断裂、异常变形或脚底漂移。
- [ ] 停止、起动、转向、攻击等实际需要的状态可以解释重量与支撑。
- [ ] 导出后的几何、法线、UV、通道、命名与动画契约已检查。

### G4 · 引擎与交付

- [ ] 已在目标引擎确认朝向、尺寸、落地、队色、透明与反射表现。
- [ ] 已测试任务实际包含的移动、攻击、生产／出入或其他动作与状态，且保留本次证据。
- [ ] 有可编辑源文件、目标格式、预览、预算统计和测试状态。
- [ ] 没有把离线预览当实机截图，没有把历史测试当成本次执行。
- [ ] 没有未经本次任务授权改变旧单位、伤害数值、阵营、寻路或全局配置。

灰模未通过先改比例；表面未通过先改密度与配色；技术或实机未通过则标明阻塞。不能用“看着像低模”抵消实际失败项。

## 10. 标准维护

- 本文维护通用风格；分支文档维护对象适配和技术限制；基准档案维护已验证案例事实。
- 新单位应记录如何沿用标准、哪些地方因类别而变化，而不是再次复制一整份规范。
- 首个生物单位完成视觉、变形和实机验收后，或首栋建筑完成风格、空间／状态与实机验收后，可以提议增补相应基准；在此之前，迁移示例仍是建议。
- 固定基准图片不跟随模型生成器自动覆盖。若要改变全项目风格，建立新版本并保留旧基准；一次重建或单个单位的例外不等于标准升级。
